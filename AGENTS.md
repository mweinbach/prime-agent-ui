# Prime Agent Desktop development

Read this before working on the desktop app. For changes inside the `harness/` Git submodule, also read [harness/AGENTS.md](harness/AGENTS.md).

- `mweinbach/prime-agent-ui` owns `crates/pa-desktop`, desktop integration tests and macOS packaging. `harness/` pins `mweinbach/prime-agent`, a fork of `PrimeIntellect-ai/prime-agent`. Never send desktop-only changes to the upstream organization by default. See [CONTRIBUTING.md](CONTRIBUTING.md).
- Run `make init` once after a nonrecursive clone. Build against the checked-in gitlink, not whatever `main` points to today. Never copy the harness out of its submodule to work around missing dependencies. Push a reachable harness commit before publishing a new pointer.
- Keep daemon and UI binaries from the same build; use the shared `target/` release cache and no more than six Cargo jobs. Use `make check` for formatting, desktop Clippy and tests. Use `make desktop-app` for the signed app. Do not start the GUI as a side effect of building or testing.
- Run UI checks with Rune’s headless runtime, a temporary profile and socket, and offline or scripted providers. Never activate an OS window on the user’s desktop without explicit permission. Do not inspect real chat contents, use real provider keys for QA, or bundle user state. Preserve drafts when switching conversations; do not replace shared CLI daemons.
- The desktop talks to the real daemon rather than running a second agent loop. Do not block paint on sockets, HTTP or telemetry. New user-visible actions should respect the existing telemetry opt-in and contain no chat, path or credential data. Fix bugs with a discriminating headless regression test.
- Use the existing Rust and Rune style; prefer focused modules, private internals, explicit crate APIs and no new dependencies when the existing ones suffice. Keep both lockfiles up to date in their respective workspaces. Keep resources in `Contents/Resources`, assemble before signing, and verify with `codesign --verify --deep --strict`.
- Never set git identity (`user.name`, `user.email` or author/committer environment overrides) for repository commits. Use the ambient configuration and never add `Co-authored-by` trailers.
